## 설치 앱에서 직접 확인한 8가지 동작

테스트 코드는 [desktop-qa.mjs](../packages/mycode/script/desktop-qa.mjs)입니다. Playwright를 설치 앱의 Chromium에 `noDefaults: true`로 연결했습니다. 브라우저 복제 화면이나 UI 목업을 사용하지 않았으며, 모델 호출은 0회입니다.

| 테스트         | 실제 확인한 결과                                                                            |
| -------------- | ------------------------------------------------------------------------------------------- |
| 메모리 저장    | UI의 Save memory로 저장하고 목록에서 내용 확인                                              |
| 메모리 검색    | parser 검색으로 저장된 규칙 검색                                                            |
| 프로젝트 격리  | 새 Git 프로젝트에는 이전 프로젝트의 메모리가 나타나지 않음                                  |
| 다시 불러오기  | 원래 프로젝트로 돌아오면 저장한 메모리가 유지됨                                             |
| 선택 항목 삭제 | 임시 메모리만 Forget으로 삭제하고 기존 규칙은 보존                                          |
| 동적 전환·증거 | 검증 실패 → 복구 → 검증 성공 → 마지막 검증 성공, 각 종료 코드와 시도 이력이 화면에 표시됨   |
| 컨텍스트·스킬  | 정리 옵션은 기본 Off. UI에서 On으로 저장하고 실제 서버 등록 목록의 스킬 3개 표시 확인       |
| 설정 격리·유지 | 다른 프로젝트는 Off, 원래 프로젝트를 다시 불러오면 On. 테스트 후 원래 프로젝트도 Off로 복원 |

이 과정에서 발견한 프로젝트 전환 시 이전 화면 데이터 잔류 문제를 수정했습니다. Solid store에서 상태 객체를 병합하던 경로를 전체 교체로 바꾸었으며, 위 프로젝트 전환 테스트로 수정된 동작을 확인했습니다.

검증 예제는 `/bin/test -f verified.txt`를 먼저 실행합니다. 파일이 없으므로 종료 코드 1을 받습니다. 복구 단계의 `/usr/bin/touch verified.txt` 후 검증 두 번이 각각 종료 코드 0을 받습니다. 이는 하네스의 실제 프로세스 실행·전환·종료 판정 검증이며 AI 코드 작성 능력의 평가가 아닙니다.
